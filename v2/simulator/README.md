# v2 분자 완화 시뮬레이터 (브라우저 단독)

학습된 신경망 퍼텐셜을 **브라우저에서 직접** 추론해 실제 힘 `F = -∂E/∂r` 방향으로 분자를 완화한다.
서버 없이 돌아간다(v1은 백엔드가 없으면 무작위 이동으로 폴백했다).

**2026-08-12: 모델을 전 데이터셋 학습본으로 교체했다.** 구모델(`nnp.pt`, SchNet류 `SimpleNNP`,
10만 파라미터, QM9x 5천개·5에포크)에서 → **`v2/fulltrain_best.pt`**(어텐션 기반 `SimpleModel`,
80만 파라미터, 5개 데이터셋 2,271만 구조 학습). 구모델 자산(`nnp.js`, `weights.json`,
`export_weights.py`)은 대조·롤백용으로 남겨 뒀다.

## 실행

빌드 없음. 정적 서버로 열면 된다(로컬 파일 `file://`은 `fetch`가 막혀 안 됨).

```
# 저장소 루트에서
python -m http.server 8000
# → http://localhost:8000/v2/simulator/
```

원소를 캔버스에 드래그/클릭으로 배치(또는 좌측 프리셋) → **시작**. 매 스텝 에너지·ΔE·|F|max가
HUD에 뜨고, 에너지가 평탄해지면 "완화 완료"로 자동 정지한다.

**에너지는 총에너지다** — 물이면 약 −76 Ha(고립원자 에너지 합 + 신경망이 예측한 결합 몫).
구모델의 −0.4 Ha와 스케일이 완전히 다르다. 완화로 실제 변하는 폭은 작으므로(0.005~0.07 Ha)
HUD의 **ΔE**를 보는 편이 낫다.

## 2D / 3D 모드

컨트롤 바의 `[2D | 3D]` 토글로 전환한다. 원자 상태는 두 모드가 **world 좌표 `[x,y,z]` Å 하나로 공유**하고,
2D는 그 중 xy만 그리며 xy 평면 안에서만 완화한다. 3D는 세 성분을 모두 완화한다.

| 조작 | 3D 모드 |
|---|---|
| 빈 공간 드래그 | 카메라 회전(orbit) — 완화 중에도 동작 |
| 휠 | 줌 (2~40 Å) |
| 원자 위 드래그 | 그 원자를 카메라 평면 안에서 이동(시작 전에만) |
| 팔레트 선택 후 클릭 / 칩 드래그&드롭 | 뷰 중심을 지나는 정면 평면에 배치 |
| `무작위 배치` | 배치된 원자들을 뷰 중심 반경 2 Å 구 안에 재배치(간격 ≥ 0.7 Å 시도) |

**공면(coplanar) 함정** — 에너지가 원자 쌍거리에만 의존하므로 모든 원자가 정확히 한 평면 위에 있으면
평면에 수직인 힘 성분이 **정확히 0**이라 완화가 영원히 평면을 못 벗어난다. 그래서 2D→3D 전환·3D 프리셋
로드 때 z 폭이 0.01 Å 미만이면 각 원자 z에 ±0.2 Å 오프셋을 한 번 주고, 3D 배치 시에도 깊이 방향으로
±0.15 Å 흔든다.

**지원 원소: H·C·N·O·F.** 학습 데이터(ANI-2x)에는 S·Cl도 있지만 팔레트에서 뺐다 — 아래 한계 참고.

## 구성

- `index.html` — UI + 완화 루프 + 모드 전환. 라이트 테마, 페이드 인 없음.
- `simple_nnp.js` — **`v2/model.py`의 `SimpleModel` 순수 JS 재구현**(신규). 계산은 전부 float64.
- `weights_simple.json` / `weights_simple.bin` — 매니페스트(config·텐서 레이아웃·`Etot_table` float64)
  + float32 가중치 블롭(3.2 MB). 80만 파라미터를 JSON 배열로 쓰면 10 MB를 넘어 바이너리로 나눴다.
- `export_simple_weights.py` — `fulltrain_best.pt` → 위 두 파일 변환 스크립트. 재학습했으면 다시 돌린다.
- `view3d.js` — 3D 뷰어. 외부 라이브러리 없이 **canvas 2D + painter's algorithm**(원자 ≤30개라 WebGL 불필요).
  렌더는 `requestAnimationFrame`, 물리 tick은 `setTimeout`이라 **완화 중에도 회전/줌이 끊기지 않는다**.
- `nnp.js` / `weights.json` / `export_weights.py` — 구모델(`SimpleNNP`) 자산. 현재 UI는 쓰지 않는다.

### 힘은 해석적 역전파로 구한다

구모델은 힘을 중심 유한차분으로 구했다(스텝당 forward 6N+1번). 새 모델은 8배 커서 그러면
원자 10개에 스텝당 61번 → 인터랙티브가 불가능하다. 그래서 **연쇄법칙을 손으로 전개해 한 번의
역전파로** 모든 좌표 미분을 얻는다. 좌표가 에너지에 들어가는 통로가 어텐션의 거리 bias 하나뿐이라
정리가 깔끔하다:

```
∂E/∂r_k = Σ_{j≠k} (G_kj + G_jk) · (r_k - r_j) / d_kj² ,   G_ij = ∂E/∂log(d_ij)
```

`G`는 energy_head → A3 → A2 → A1 순으로 한 번 역전파하면 나온다. 검증용 유한차분 구현
(`energyAndForcesFD()`)도 남겨 뒀다.

### 검증 (2026-08-12 실측)

PyTorch 원본(`v2/model.py` + `fulltrain_best.pt`)과 7개 분자(H₂O·NH₃·CH₄·HCN·H₂S·CH₃Cl·혼합 7원자) 대조:

| 항목 | 최대 오차 |
|---|---|
| 에너지 (JS vs PyTorch) | 5.6e-7 Ha |
| 힘 (JS 해석적 vs PyTorch autograd) | 6.1e-7 Ha/Å |
| 힘 (JS 해석적 vs JS 유한차분) | 5.6e-8 Ha/Å |

성능(1스텝 = 에너지+힘 1회, Node 기준):

| 원자 수 | 3 | 5 | 10 | 20 |
|---|---|---|---|---|
| ms/스텝 | 16 | 21 | 63 | 188 |

원자 5개 이하는 쾌적하고, 10개를 넘으면 눈에 띄게 느려진다(20개면 스텝당 0.2초).

## 완화 파라미터 (`index.html` 상단 상수)

| 상수 | 값 | 뜻 |
|---|---|---|
| `STEP_LR` | 0.3 | 최속강하 학습률(Å per Ha/Å) — 구모델 1.5에서 5배 축소 |
| `STEP_CLIP` | 0.01 | 스텝당 최대 이동(Å) — 구모델 0.04에서 4배 축소 |
| `CONV_WIN` / `CONV_TOL` | 16 / 3e-4 | 최근 16스텝 에너지 변동 < 3e-4 Ha면 완화 완료 |
| `TICK` | 40 | 스텝 간격(ms). 추론이 20~60 ms라 실제 주기는 그만큼 더 길다 |
| `BOND_MAX` | 1.8 | 결합선 표시 거리(Å) — 화학 판정이 아니라 시각 표시 |
| `PLANE_TOL` / `SCATTER_PLANE` / `SCATTER_PLACE` | 0.01 / 0.2 / 0.15 | 공면 판정·흩뿌림·배치 오프셋(Å) |
| `RAND_RADIUS` / `RAND_MIN_D` | 2.0 / 0.7 | 무작위 배치 구 반경 / 최소 간격(Å) |

**LR·CLIP을 줄인 이유**: 이 모델에는 단거리 반발벽이 없다(`model.py`에서 핵간쿨롱 항을 뺐다 —
학습 안정성 때문). 큰 스텝을 쓰면 원자가 서로 뚫고 들어가 0.2~0.7 Å로 붕괴한다.

### 프리셋 완화 결과 (3D, 위 상수, 실측)

| 분자 | 수렴 | ΔE (kcal/mol) | 최종 결합거리 (실제값) |
|---|---|---|---|
| H₂O | 32스텝 | −4.8 | O–H 0.92 (0.96) |
| NH₃ | 23스텝 | −3.6 | N–H 1.08 ×3 (1.01), 완전 대칭 |
| CH₄ | 36스텝 | −14.9 | C–H 1.06 ×4 (1.09), H–H 1.73 ×6 → **정확한 정사면체** |
| HCN | 38스텝 | −11.2 | H–C 1.05 (1.07), C–N 1.55 (1.16 — 과대) |
| CH₂F₂ | 74스텝 | −45.0 | C–F 1.31 (1.36), C–H 1.04 (1.09) |

구모델은 CH₄에서 C–H가 0.95 Å 셋 + 1.33 Å 하나로 찌그러졌는데, 새 모델은 정사면체를 정확히 재현한다.

## 한계 (실측 기반)

- **S·Cl는 팔레트에서 제외했다.** 모델은 학습했지만 완화가 불안정하다 — CH₃Cl을 완화시키면
  C–Cl이 **0.26 Å로 붕괴**하고 수렴하지 않는다(|F|max 1.9). 단거리 반발벽이 없어 이 영역에서
  모델이 잘못 외삽하는 탓이다. H₂S는 수렴하지만 S–H = 1.66 Å로 실제 1.34에서 크게 벗어난다.
  쓰려면 차폐(screened/ZBL)형 반발 항을 모델에 넣어야 한다.
- **초기 배치가 나쁘면 결과도 나쁘다.** 프리셋은 실제 구조에서 결합만 ~15% 늘린 3D 좌표를 쓴다.
  예전처럼 평면에 대충 흩어 놓고 시작하면(원자 간격 0.5 Å 등) CH₄가 H–H 0.83 Å 같은 붕괴 구조로 수렴한다.
- **2D 모드는 z를 고정**한 채 xy 평면에서만 완화하므로 3D 분자를 눕혀 푸는 셈이다. 제대로 된 구조는 3D 모드에서 나온다.
- HCN의 C≡N처럼 삼중결합은 아직 길게 나온다(1.55 vs 실제 1.16).
- 결합선은 거리 < 1.8 Å 표시일 뿐 화학 결합 판정이 아니다.

## AWS 백엔드 (미구현 — 나중에 개발)

`index.html` 상단 `API_BASE`가 **비어 있어("") 지금은 브라우저 추론만 한다.** 나중에 GPU 서버가
필요해지면 여기에 URL을 넣으면 매 스텝 `POST /step`을 먼저 호출하고, **연결이 안 되면 자동으로
브라우저 모델로 폴백**한다. 서버 계약은 v1과 동일:

```
POST /step
  { "atoms": [{"element":"O","x":..,"y":..,"z":0}, ...], "dt": 10.0 }
→ { "atoms": [[x,y,z], ...], "energy": <Ha> }
```

v1 `backend/main.py`가 이 계약의 FastAPI 골격을 갖고 있으니 `SimpleModel` + `fulltrain_best.pt`를
물리는 쪽으로 바꿔 붙이면 된다. **단, 지금은 구현하지 않는다.**
