# v2 분자 완화 시뮬레이터 (브라우저 단독)

v1(`demo/` + `backend/`)의 완화 데모를 v2로 옮긴 것. **가장 큰 차이는 진짜 모델이 돈다는 점**이다.
v1은 EC2 백엔드가 없으면 로컬 무작위 이동으로 폴백했지만, v2는 학습된 `v2/nnp.pt`(`SimpleNNP`)를
**브라우저에서 직접** 추론해 실제 힘 `F = -∂E/∂r` 방향으로 분자를 완화한다.

## 실행

빌드 없음. 정적 서버로 열면 된다(로컬 파일 `file://`은 `fetch`가 막혀 안 됨).

```
# 저장소 루트에서
python -m http.server 8000
# → http://localhost:8000/v2/simulator/
```

원소를 캔버스에 드래그/클릭으로 배치(또는 좌측 프리셋) → **시작**. 매 스텝 에너지·|F|max가 HUD에 뜨고,
에너지가 평탄해지면 "완화 완료"로 자동 정지한다.

## 2D / 3D 모드

컨트롤 바의 `[2D | 3D]` 토글로 전환한다. 원자 상태는 두 모드가 **world 좌표 `[x,y,z]` Å 하나로 공유**하고,
2D는 그 중 xy만 화면에 그리며 xy 평면 안에서만 완화한다. 3D는 세 성분을 모두 완화한다.

| 조작 | 3D 모드 |
|---|---|
| 빈 공간 드래그 | 카메라 회전(orbit) — 완화 중에도 동작 |
| 휠 | 줌 (2~40 Å) |
| 원자 위 드래그 | 그 원자를 카메라 평면 안에서 이동(시작 전에만) |
| 팔레트 선택 후 클릭 | 뷰 중심을 지나는 정면 평면에 배치 |
| 팔레트 칩 드래그&드롭 | 같은 평면에 배치 |
| `무작위 배치` | 배치된 원자들을 뷰 중심 반경 2 Å 구 안에 재배치(간격 ≥ 0.7 Å 시도) |

**공면(coplanar) 함정** — 에너지가 원자 쌍거리에만 의존하므로 모든 원자가 정확히 한 평면 위에 있으면
평면에 수직인 힘 성분이 **정확히 0**이라 완화가 영원히 평면을 못 벗어난다(평면 CH₄를 100스텝 돌려도
z 폭 = 0.00e+0 Å). 그래서 2D→3D 전환·3D에서의 프리셋 로드 때 z 폭이 0.01 Å 미만이면 각 원자 z에
±0.2 Å 무작위 오프셋을 한 번 주고, 3D에서 원자를 놓을 때도 깊이 방향으로 ±0.15 Å 흔든다.

**지원 원소: H·C·N·O·F** — 모델이 학습한 QM9x 5종뿐이다(임베딩 `MAX_Z=10`). S·Cl 등을 쓰려면
ANI-2x로 재학습하고 `MAX_Z`를 늘려야 한다. 결합선은 화학 판정이 아니라 **거리 < 1.8 Å**인 쌍을
잇는 시각적 표시일 뿐이다.

## 구성

- `index.html` — UI + 완화 루프 + 모드 전환. v1 `demo/index.html`의 외형·조작을 유지(라이트 테마, 페이드 인 없음).
- `view3d.js` — 3D 뷰어. 외부 라이브러리 없이 **canvas 2D + painter's algorithm**으로 그린다(원자 ≤30개라
  WebGL 불필요). 매 프레임 (원근 투영 → 깊이 정렬 → 뒤에서 앞으로)만 하면 되고, 렌더는 `requestAnimationFrame`
  루프라 물리 tick(`setTimeout`, 60 ms)과 분리돼 **완화 중에도 회전/줌이 끊기지 않는다**. 카메라는
  target(뷰 중심) 기준 orbit(yaw/pitch/dist). 깊이에 따라 색을 밝은 배경 쪽으로 섞어 원근감을 준다.
- `nnp.js` — `v2/model.py`의 `SimpleNNP` **순수 JS 재구현**. 에너지는 forward 그대로,
  힘은 JS에 autograd가 없어 `F = -∂E/∂r`을 **중심 유한차분**으로 구한다(원자 수가 적어 스텝당
  forward 6N번이면 충분). PyTorch 원본과 에너지 오차 ~1e-8 Ha, 힘 오차 ~1e-6 Ha/Å로 일치 확인.
- `weights.json` — `nnp.pt`의 가중치를 JSON으로 export한 것(약 1MB).
- `export_weights.py` — `nnp.pt` → `weights.json` 변환 스크립트.

### weights.json 재생성

`nnp.pt`를 다시 학습(`python v2/train.py`)했으면 가중치도 다시 뽑는다:

```
python v2/simulator/export_weights.py
```

`state_dict`를 그대로 JSON 배열로 옮길 뿐이다(`embedding`, 블록별 `filters`/`updates`,
`readout`, `centers` 버퍼 + `config`).

## 완화 파라미터 (`index.html` 상단 상수)

| 상수 | 값 | 뜻 |
|---|---|---|
| `STEP_LR` | 1.5 | 최속강하 학습률(Å per Ha/Å) |
| `STEP_CLIP` | 0.04 | 스텝당 최대 이동(Å), 발산 방지 |
| `CONV_WIN` / `CONV_TOL` | 16 / 3e-4 | 최근 16스텝 에너지 변동 < 3e-4 Ha면 완화 완료 |
| `PLANE_TOL` / `SCATTER_PLANE` | 0.01 / 0.2 | 공면 판정 z 폭(Å) / 흩뿌림 진폭(Å) |
| `SCATTER_PLACE` | 0.15 | 3D 배치 시 깊이 방향 오프셋(Å) |
| `RAND_RADIUS` / `RAND_MIN_D` | 2.0 / 0.7 | 무작위 배치 구 반경 / 최소 간격(Å) |

같은 상수를 두 모드가 공유한다. 이 값에서 H₂O/NH₃/CH₄/HCN 프리셋이 18~60스텝(약 1~4초)에 수렴한다
(3D CH₄ + z 오프셋 기준 46스텝, ΔE = −0.027 Ha). `nnp.pt`가 5에포크만 학습된 모델이라 힘이 완전히
0으로는 안 떨어지므로(잔여 힘 ~0.02 Ha/Å), **에너지 평탄화**를 수렴 신호로 쓴다. 그래도 H₂O는
O–H ≈ 0.96 Å로 실제값에 가깝게 안착한다.

**한계**: 2D 모드는 z를 고정한 채 xy 평면 안에서만 완화하므로 3D 분자를 눕혀 푸는 셈이고, 프리셋에
따라 H 하나가 평면에서 어정쩡하게 남는다 — 제대로 된 구조는 **3D 모드**에서 나온다. 3D에서도 결합선은
화학 판정이 아니라 거리 < 1.8 Å 표시일 뿐이고, 5에포크 모델이라 결합 길이가 실제값에서 꽤 벗어날 수 있다
(예: 위 CH₄ 완화 결과의 C–H가 0.95 Å 셋 + 1.33 Å 하나).

## AWS 백엔드 (미구현 — 나중에 개발)

`index.html` 상단 `API_BASE`가 **비어 있어("") 지금은 브라우저 추론만 한다.** 나중에 GPU 서버가
필요해지면(더 큰 모델/분자) 여기에 서버 URL을 넣으면 된다. 그러면 매 스텝 `POST /step`을 먼저
호출하고, **연결이 안 되면 자동으로 브라우저 모델로 폴백**한다. 서버 계약은 v1과 동일하게 잡아 뒀다:

```
POST /step
  { "atoms": [{"element":"O","x":..,"y":..,"z":0}, ...], "dt": 10.0 }
→ { "atoms": [[x,y,z], ...], "energy": <Ha> }
```

v1 `backend/main.py`가 이 계약의 FastAPI 구현 골격(모델 1회 로드·세마포어·CORS)을 이미 갖고 있으니,
`SimpleNNP` + `nnp.pt`를 물리는 쪽으로 바꿔 붙이면 된다. **단, 지금은 구현하지 않는다.**
